# 片场使用与部署手册

## 部署选择

提供 Docker、pip 与源码安装三种方式。

需要 Python 3.11 或 3.12。源码可通过 git clone 下载整个仓库，也可下载仓库 ZIP 解压，随后进入 video-studio 目录。当前未发布 PyPI 包或预构建镜像，请勿直接安装网上同名包。

### Docker Compose

安装 Docker 和 Compose 后，在 video-studio 目录执行：

```sh
docker compose up -d --build
docker compose logs -f
docker compose down
```

访问 http://127.0.0.1:4180。容器内 API 由 UI 访问，不映射 API 端口。数据与密钥保存在 studio-data 命名卷；down 不删除数据，请勿使用 down -v。升级前停止服务并备份该卷，然后更新源码、重新构建。
容器未安装 Codex CLI，模型设置请选择 API 渠道。容器中的路径指容器文件系统，本机素材请通过界面上传。

### pip 安装本地仓库或下载包

在 video-studio 目录执行：

```sh
python3.11 -m venv .venv-pip
source .venv-pip/bin/activate
python -m pip install uv
python -m pip install --no-deps -r requirements.txt
python -m pip install --no-deps .
video-studio
```

Windows 激活命令为 `.venv-pip\Scripts\activate`。requirements.txt 从锁文件导出，先安装依赖再安装应用，以遵循项目的 Pillow 兼容覆盖；pip check 可能报告 MoviePy 的已知 Pillow 上限冲突。应用优先使用系统 FFmpeg，未找到时使用 Python 依赖附带的 FFmpeg；Linux 也可安装 ffmpeg 和 fonts-noto-cjk，macOS 可通过 Homebrew 安装 ffmpeg。pip 安装默认数据目录为用户目录下 `.video-studio`，可用 STUDIO_DATA 覆盖。

### 锁定源码安装

```sh
uv sync --frozen --no-dev
uv run --frozen video-studio
```

macOS 如需保留已有钥匙串授权，继续从仓库根目录使用 `./video-studio/install-quick.sh` 和 `./video-studio/run.sh`，沿用原有双环境启动。

## 首次使用

1. 打开设置，选择总导演、图像、视频等角色的平台与模型，填写自己的 API Key。连接测试仅验证相应接口，不保证所有生成能力可用。
2. 在项目总览创建项目，选择快速生成或自定义制作。
3. 快速生成：准备文案与素材，选择配音、字幕并提交合成；在线配音和素材服务需要网络及对应凭据。
4. 自定义制作：按故事、分镜、画风、首尾帧、提交前准备、逐镜生成、合成顺序操作。先核对模型、分辨率、时长与预算，再提交生成。
5. 在项目中预览并下载成片；在素材页管理素材，在调用日志中查询结果、用量并导出 CSV。

## 数据、安全与维护

STUDIO_DATA 保存数据库、素材、引擎配置与产物。macOS 使用钥匙串；Linux/Windows 使用该目录下权限为 0600 的 secrets.json 明文密钥文件，应保护整个目录及备份。Windows 还需通过系统目录权限限制访问。memory 密钥模式仅用于测试，重启丢失密钥。

默认端口 UI 4180、API 4173，可通过 STUDIO_UI_PORT 和 PORT 调整。STUDIO_BIND 仅用于容器内部监听。应用面向单人本机使用，Compose 仅发布到本机回环地址，不应直接开放公网。

备份前停止应用，复制整个数据目录；恢复时停止服务并还原该目录。macOS 钥匙串凭据不在目录备份内，迁移后可能需重新填写。

无法访问：检查进程日志与端口占用。引擎未就绪：检查安装环境和 STUDIO_PYTHON 是否指向已安装媒体依赖的 Python。合成失败：检查 FFmpeg、素材有效性、磁盘空间和字体。在线任务失败：检查网络、模型权限及平台余额，费用以平台账单为准。更新代码前备份数据，更新后重新同步依赖并重启。

基础镜像拉取受限时，可使用 `docker compose build --build-arg PYTHON_IMAGE=public.ecr.aws/docker/library/python:3.11-slim`，随后运行 `docker compose up -d`。该地址为公共镜像源，默认仍使用 Docker Hub。

## 安装后验证

`pip` 安装使用完整的 requirements.txt 加 `--no-deps`，避免安装器重新解析并否定已锁定的兼容覆盖。不要仅运行 `pip install .`。已知 MoviePy/Pillow 元数据冲突保留在 pip check 输出中，应用以离线合成测试验证实际兼容性。

启动后访问 `/api/health`（默认 API 地址 http://127.0.0.1:4173），应返回 ok 和 ffmpeg 为 true；UI 健康地址为 http://127.0.0.1:4180/_stcore/health。Docker Compose 会自动检查两个服务。

维护者可使用 `STUDIO_TEST_ROOT` 指定已安装应用目录、`STUDIO_TEST_PYTHON` 指定独立环境 Python，执行 `test_bundled_engine.py`，验证资源清单、依赖兼容覆盖与断网合成。测试无需服务商密钥。
